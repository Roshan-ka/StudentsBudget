# StudentsBudget P1.1 Implementation Plan: feedback round

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** turn Roshan's first-use feedback into the app. In short:
- charts that open as a donut, with style and period options, plus income and savings
- fixed costs and income that post themselves on their day, editable in Settings
- more basic categories
- a Home that leads with the month and offers a suggested budget
- dates shown as DD-MM-YYYY with a Today shortcut
- a backup restore that checks the file properly and says what it will replace

**Spec:** `docs/Student Budget App - Concept.md` ([[Student Budget App - Concept]]), updated in the same commit as this plan. The P1 plan ([[2026-10-16-p1-test-project|P1 plan]]) still describes everything this plan doesn't change.

**Architecture:** unchanged from P1. The changes are:
- optional `schedule` fields on the plan's income and fixed lines
- an optional `recurring` marker on entries
- backup format version 2

There is no new Dexie table and no `db.version` bump, because the new fields are optional and add no index.

## Global Constraints
**Code**
- TypeScript `strict`; no `any`.
- **Money:** integer minor units (`Minor`), never floats.
  - Plan, envelope and city amounts are in EUR.
  - Each entry keeps its account's currency in `amountMinor`, plus `eurMinor` converted at save time. For a recurring entry, conversion happens when it's posted.
- **Dates:**
  - Stored as local `IsoDate` (`YYYY-MM-DD`) and `IsoMonth` (`YYYY-MM`) strings.
  - **Shown** as `DD-MM-YYYY` wherever a full date appears (`formatDate`). Short labels like "Mon 26 Oct" stay.
  - Weeks run Monday–Sunday, and the check-in is on Sunday.
- **Data:** everything lives in the IndexedDB database `studentsbudget`. Never query Dexie during render.

**What stays out**
- No AI calls, server routes, login, analytics or third-party scripts.
- The only outgoing request is Frankfurter (`https://api.frankfurter.dev/v1/latest?base=EUR&symbols=…`).
- No Vercel: nothing is deployed in this round.
- No new npm dependencies without a controller ruling.

**Text and layout**
- UI language is English.
- Money is formatted with `Intl.NumberFormat('en-IE', …)`: `€6.50`, and `€63` for headlines.
- Calm wording: "€12 over", never "failed" or "warning!".
- Phone first: works at 375 px, with 16 px side gutters, no horizontal page scroll and bottom navigation.

**Data rules**
- City: Regensburg only. Every city number has a source, a URL and a checked date; a number without one is labelled "Estimate".
- Guesses are saved once in setup and never edited afterwards. They cover the original 6 flexible categories only.

**Repo**
- Everything is committed and pushed only to `SupportRW/StudentsBudget`. Nothing goes to other repos.
- One branch, `feat/p1-1-feedback`, with one Draft PR. Roshan merges.
- Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Exact pins (`.npmrc` `save-exact=true`), listed in `CLAUDE.md`.

**Interfaces (Produces):**
```ts
// schedule.ts
export function periodOf(s: Schedule, d: IsoDate): { start: IsoDate; end: IsoDate }; // calendar month, or Mon–Sun week
export function occurrenceIn(s: Schedule, periodStart: IsoDate): IsoDate;          // monthly: min(day, last day); weekly: Monday + day − 1
export function duePeriods(s: Schedule, today: IsoDate): IsoDate[];                // period starts, oldest first: occurrence in [startOn, today] and period end > postedThrough; [] when paused
export function monthlyEquivalent(s: Pick<Schedule, 'frequency' | 'amountMinor'>): Minor; // weekly: round(amount × 52 / 12)
// post-due.ts
export function recurringEntryId(scheduleId: string, periodStart: IsoDate): string; // 'rec:<scheduleId>:<periodStart>'
export async function postDueRecurring(today: IsoDate): Promise<{ posted: number }>;
// update-plan.ts
export async function updatePlan(mutate: (plan: Plan) => Plan): Promise<void>; // read + write in one rw transaction; keeps each schedule's postedThrough
```

**Rules:**
- **Posting** (`postDueRecurring`):
  - It runs in **one** `rw` transaction over `plan`, `entries`, `accounts` and `fxRates`, and reads the plan inside it.
  - Calls are queued at module level, so concurrent calls run one after another.
  - For each income or fixed line whose `schedule` isn't paused, it posts each due period, oldest first, as an entry:
    - `type: 'income'` or `'expense'` for that line's `categoryId`, on the occurrence date
    - `amountMinor` = `schedule.amountMinor`, with `eurMinor` converted with the rate in use, as for a manual entry
    - `note` = the category name
    - `recurring: { scheduleId }` and id `recurringEntryId(...)`
  - It skips ids that already exist (`bulkGet`).
  - It then sets `postedThrough` to the end of the last handled period.
  - **No rate for a non-EUR account:** stop that line before the period, leave its watermark where it is, and retry on the next run.
  - **Missing account:** skip the line. The editor shows "Pick an account for this".
- **New or resumed lines** get `startOn = tomorrow` and `postedThrough = today`. There's no back-posting, and a resume skips the paused periods.
- **Changing amount, day, frequency or account** touches neither field, so the change applies from the next occurrence.
- **A deleted occurrence** sits below the watermark and never comes back.
- **AppInit** calls `postDueRecurring(todayIso())` after `ensureSeeded`, once the first `refreshRates` has settled (success or failure), and again on each `visibilitychange` to visible, after that refresh.
- **Setup** (income, fixed, and rent in the city-rent or fixed step), for each line with an amount above 0:
  - a toggle "Add it automatically" (default on)
  - "Monthly on day [1–31]" or "Weekly on [Mon–Sun]"
  - "Account [select]"
  - for a non-EUR account, "Amount in INR" (or that account's currency). Setup has no rate, so it can't convert. The EUR monthly amount stays the plan figure.
  - Draft accounts get draft-local keys until save.
  - The helper text reads: "It's added on its day — don't log it by hand."
- **Settings → "Fixed costs and income"** (the editor) lists every income and fixed line with its amount, schedule and account. You can:
  - edit the amount, day, frequency or account
  - pause or resume
  - turn auto-adding off or on
  - delete the line
  - add a line, from the fixed and income categories not yet in the plan
  - Every save goes through `updatePlan`.
  - If the plan is over what's available, a calm line shows "Your plan is €X over your income" (`planSummary.overByMinor`).
  - "Edit plan" stays for envelopes and one-offs.
- **The e2e helpers** (`fillSetup` / `completeSetup`) turn "Add it automatically" off unless a test passes `schedules: true`.
